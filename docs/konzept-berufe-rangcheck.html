Berufe-Rangcheck: R2/R3 zeigen den Beruf

Im Spiel steht der Beruf nicht in der Mitgliederliste, aber der Rang schon. Wenn die Allianz R2 und R3 nach Beruf vergibt, sieht der Berufeplaner sofort, wer falsch einsortiert ist. Der Scanner pflegt die Ränge laufend und meldet Abweichungen. Aufgaben stehen in der Aufgabenliste.

🎯 Idee in einem Satz

R2 = Ingenieur, R3 = Kriegsherr (oder andersherum, pro Allianz einstellbar). Steht im Planer ein R2 bei den Kriegsherren, zittert seine Kachel und zieht zur richtigen Seite. Verschoben wird weiter per Drag-and-drop. Bei R1, R4 und R5 lässt sich der Beruf so nicht ablesen, diese Kacheln bleiben neutral.

🛡 Rangwappen

Jede Kachel zeigt den Rang als Ziffer in einem gelben Wappen. Gilt immer, auch ohne Rangcheck. Der Name eines Rangs („Elite“ usw.) wird nicht gezeigt, damit niemand falsch benannt wird.

🎨 Farbe + Zittern

Nur wenn der Rangcheck an ist: Hintergrund leicht nach erwartetem Beruf getönt, falsche Kacheln zittern und lehnen sich zur richtigen Spalte.

✉ Spieler fragen

Winziger Knopf an jeder Kachel. Öffnet den vorbereiteten Text aus der Vorlage und kopiert ihn in die Zwischenablage, fertig zum Einfügen in die Spielmail.

📡 Scanner-Rückmeldung

Der Sync antwortet zusätzlich mit einer Liste falsch einsortierter Spieler. Kein Upload wird verhindert. Liste per Knopf kopieren und in den R4-Chat geben.

👀 So soll es aussehen

Vorschau mit Einstellung R2 = Ingenieur, R3 = Kriegsherr. Die Spalte Kriegsherr liegt im Planer links, die Ingenieur-Slots rechts. Darum lehnt sich ein falscher Kriegsherr nach rechts und ein falscher Ingenieur nach links.

Die Prüfung läuft ausschließlich im Browser aus Daten, die schon da sind: PREV[name] (Rang) und memberMeta[name].beruf. Dazu kommt eine kleine Hilfsfunktion:

function bpExpectedBeruf(rank) {           // null = nicht prüfbar
  if (!isBerufRankCheckOn()) return null;
  const r2 = flagConfig.berufe_rangcheck_r2 === 'kriegsherr' ? 'kriegsherr' : 'ingenieur';
  if (rank === 2) return r2;
  if (rank === 3) return r2 === 'ingenieur' ? 'kriegsherr' : 'ingenieur';
  return null;
}
// Status: 'ok' | 'wrong' | 'open' | null

⚙️ Einstellungen (pro Allianz)

Gespeichert in alliance_config neben berufe_max_ingenieure, geladen über loadFlagConfig(). Ändern dürfen R4/R5 (wie die anderen Berufe-Einstellungen).

Im Planer-Kopf ein Schalter „Rangcheck R2/R3“ mit kleinem Auswahlfeld „R2 = Ingenieur / R2 = Kriegsherr“ und ein Zähler „3 falsch einsortiert“. Klick auf den Zähler scrollt zur ersten falschen Kachel.

✉ „Spieler fragen“

Kleiner Knopf (18 px) an jeder Kachel, in Warteschlange, Kriegsherr-Spalte und Ingenieur-Slots. Der Knopf startet kein Drag. Ablauf:

  1. Text aus der Vorlage in der Sprache des Spielers (preferred_language), sonst Deutsch.
  2. Variablen ersetzen, Text in ein kleines Fenster mit Textfeld (bearbeitbar) und gleich in die Zwischenablage.
  3. Knopf „Nochmal kopieren“ und „Schließen“. Gesendet wird im Spiel von Hand.

Die Vorlagen werden in einem kleinen Editor im Planer gepflegt (Sprache wählen, Text bearbeiten, Variablen als Klick-Chips zum Einfügen, Vorschau mit einem Beispielspieler).

📡 Scanner: Rückmeldung nach dem Sync

POST /scans/sync bekommt im Antwort-JSON ein zusätzliches Feld. Es wird nach dem Rangabgleich berechnet, also mit dem Rang, der nach diesem Scan gilt. Auch beim dry_run. Ist der Rangcheck aus, fehlt das Feld oder es ist leer. Alte Clients ignorieren es einfach.

"beruf_mismatches": [
  { "name": "Kiwi", "player_id": "…", "rank": 2, "beruf": "kriegsherr",
    "expected": "ingenieur", "rank_changed": true, "old_rank": 3 },
  …
]

rank_changed zeigt, ob der Scan den Rang gerade erst geändert hat. Das sind meist die interessanten Fälle (Beruf gewechselt, Planer noch alt). Die Rolle scanner ändert keine Ränge. Sie bekommt die Liste trotzdem, berechnet mit dem gespeicherten Rang.

Anzeige im Web-Scanner (und später in der App)

Unter der Sync-Zusammenfassung ein Block „Beruf passt nicht zum Rang (n)“ mit Knopf Liste kopieren. Kopiertext für den R4-Chat:

Berufe-Check NxU1 (Scan 26.10.)
R2 = Ingenieur · R3 = Kriegsherr
⚠ Kiwi – R2, eingeteilt als Kriegsherr (Rang neu, vorher R3)
⚠ Bolt – R3, eingeteilt als Ingenieur
Nur Hinweis, keine Sperre: Der Upload läuft immer vollständig durch. Der Beruf im Hub wird vom Scanner nicht automatisch umgestellt. Das bleibt eine Entscheidung im Planer.

🚫 Bewusst nicht dabei

  • Kein Ablesen des Berufs bei R1, R4, R5 und Ehrenmitgliedern.
  • Kein automatisches Umsortieren, weder im Planer noch beim Scan.
  • Kein Versand von Spielmails aus dem Hub. Nur Zwischenablage.
  • Keine neue Tabelle. Alles läuft über alliance_config und vorhandene Spalten.
