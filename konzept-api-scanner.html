Integration: Thomas’ Android-App, Web-Scanner & lwhub.de

Automatisierter Datenabgleich von Mitgliederlisten, Kampfkraft, Spenden, VS-Punkten & Events – inklusive Archiv-Wiederherstellung und allianzübergreifendem Transfer via Schnittstelle.

🎯 1. Ziele & Kernanforderungen

Thomas entwickelt eine Android-App (Last-War-Tracker mit MediaProjection & ML Kit OCR), während auf dem Desktop unser Web-Scanner (RapidOCR) läuft. Beide Tools sollen nahtlos mit lwhub.de vernetzt werden.

📋 Mitgliederliste abrufen

Scanner und App laden die aktuelle Namensliste inkl. bekannter Aliase/Schreibweisen, um OCR-Fehler sofort korrigieren zu können.

🔄 Intelligenter Datenabgleich

Wird ein Mitglied erkannt, prüft das Backend automatisch: Ist es aktiv? Liegt es im Archiv? Ist es in einer Partnerallianz?

🚀 Transfer & Restore per API

Keine doppelten Datensätze: Spieler aus dem Archiv werden reaktiviert; Wechsler aus anderen Allianzen werden automatisch transferiert.

⚔️ Kampfkraft, Spenden, Events

Erweiterung des Datenmodells für historische Zeitreihen (Power, Spenden Tag/Woche, VS-Punkte, Kills, Desert Storm, Zombie Siege).

🧠 2. Der „Smart-Insert“ Entscheidungsbaum

Spieler wechseln häufig zwischen Main- und Ausweichallianzen oder pausieren im Archiv. Beim Erfassen eines Namens führt die API folgenden Workflow durch:

1. Name durch Scanner erkannt (z. B. „Lion Tooth“) Scan-Input
Egal ob über Thomas’ Handy oder den Web-Scanner – der Name trifft per Batch-Sync ein.
↓
Fall A: Bereits aktiv in der Ziel-Allianz? Standard-Update
Aktion: Momentanwerte aktualisieren (Kampfkraft, HQ-Level, Status) + neuen Datenpunkt in player_metrics schreiben.
↓ Nein
Fall B: Befindet sich der Spieler im Archiv (archived_players)? Automatischer Restore
Aktion: Spieler wird vollständig aus dem Archiv zurückgeholt. Seine frühere player_id, Discord-ID und bisherigen Wochen-Einträge bleiben erhalten. Allianz wird auf die Ziel-Allianz gesetzt.
↓ Nein
Fall C: Ist der Spieler in einer ANDEREN Allianz aktiv? Allianz-Transfer
Aktion: Schnittstellen-Transfer analog zur internen R5-Transferfunktion. Spieler, Identität, Namenshistorie und Einträge werden auf die neue Allianz umgeschrieben (ohne Datenverlust).
↓ Nein
Fall D: Vollständig neuer Spieler Neuanlage
Aktion: Reguläres INSERT INTO players mit neuer UUID und erstem Eintrag in der Namenshistorie.

🗄️ 3. Datenmodell-Erweiterung (100% kompatibel)

Die bestehende Seite (lwhub.de) und das Tabellensystem für Ränge und Flags dürfen keinesfalls gestört werden. Daher erweitern wir das Schema rein additiv:

A. Aktuelle Snapshot-Werte direkt in players

Für blitzschnellen Zugriff in der Mitgliederliste und der Web-Verwaltung:

ALTER TABLE players 
    ADD COLUMN current_power BIGINT NULL DEFAULT NULL,
    ADD COLUMN hq_level TINYINT NULL DEFAULT NULL,
    ADD COLUMN last_scanned_at DATETIME NULL DEFAULT NULL,
    ADD COLUMN last_seen_status VARCHAR(100) NULL DEFAULT NULL;

B. Universelle Zeitreihen-Tabelle player_metrics

Nimmt jeden einzelnen Scan auf. Funktioniert für Kampfkraft, Spenden, Kills und beliebige künftige Events:

CREATE TABLE IF NOT EXISTS player_metrics (
    metric_id CHAR(36) NOT NULL,
    alliance VARCHAR(50) NOT NULL,
    player_id CHAR(36) NOT NULL,
    metric_type VARCHAR(40) NOT NULL, -- 'POWER', 'DONATION_WEEK', 'DONATION_DAY', 'VS_WEEK', 'VS_DAY', 'KILLS', 'DESERT_STORM', etc.
    value_numeric BIGINT NULL,
    value_text VARCHAR(255) NULL,
    extra_json JSON NULL,             -- z. B. Task Force A/B, geschaffte Wellen bei Zombie Siege
    source VARCHAR(50) NOT NULL,      -- 'android_app', 'web_scanner', 'manual'
    recorded_at DATETIME NOT NULL,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (alliance, metric_id),
    KEY ix_metrics_player (alliance, player_id, metric_type, recorded_at),
    KEY ix_metrics_type_time (alliance, metric_type, recorded_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

C. API-Tokens für App und Scanner api_tokens

CREATE TABLE IF NOT EXISTS api_tokens (
    token_id CHAR(36) NOT NULL,
    alliance VARCHAR(50) NOT NULL,
    token_hash VARCHAR(128) NOT NULL,
    client_name VARCHAR(100) NOT NULL, -- z. B. 'Thomas Android App', 'Desktop Scanner'
    role VARCHAR(20) NOT NULL DEFAULT 'scanner', -- 'scanner', 'r4', 'r5'
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    last_used_at DATETIME NULL,
    is_active TINYINT(1) NOT NULL DEFAULT 1,
    PRIMARY KEY (token_id),
    KEY ix_token_hash (token_hash)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

🔌 4. Neue & erweiterte API-Schnittstellen

Authentifizierung

Alle Anfragen von Thomas’ App oder dem Scanner senden einen Bearer-Token im HTTP-Header:

Authorization: Bearer lwhub_sec_xxxxxxxxxxxxxxxxxxxxxxxx

1. Mitgliederliste abrufen: GET /api/members

Liefert die aktive Mitgliederliste inklusive Aliasen für den OCR-Namensabgleich:

// Response (200 OK)
[
  {
    "id": "e3a89012-...",
    "name": "Lion Tooth",
    "rank": 4,
    "current_power": 164200000,
    "hq_level": 31,
    "last_seen_status": "Online",
    "last_scanned_at": "2026-10-12 18:30:00",
    "aliases": ["LionTooth", "Lion Tooth", "L1on Tooth"]
  },
  ...
]

2. Batch-Sync von Scan-Sitzungen: POST /api/scans/sync

Ermöglicht das Hochladen einer vollständigen Erfassungssitzung (z. B. 100 Mitglieder) in einer einzigen atomaren Transaktion:

// Request Body
{
  "alliance": "INY",
  "scan_type": "POWER", // oder 'DONATION_WEEK', 'VS_DAY', 'MEMBERS_LIST'
  "recorded_at": "2026-10-12T19:00:00Z",
  "source": "android_app",
  "options": {
    "auto_restore": true,    // Spieler im Archiv automatisch zurueckholen
    "auto_transfer": true   // Spieler aus Partnerallianzen transferieren
  },
  "entries": [
    {
      "name": "Lion Tooth",
      "value_numeric": 164200000,
      "hq_level": 31,
      "rank": 4,
      "status": "Online"
    },
    {
      "name": "Rückkehrer77",
      "value_numeric": 120500000,
      "hq_level": 30
    }
  ]
}
// Response (200 OK)
{
  "ok": true,
  "summary": {
    "total": 2,
    "updated": 1,
    "restored_from_archive": 1,
    "transferred": 0,
    "created_new": 0
  },
  "details": [
    { "name": "Lion Tooth", "action": "updated", "player_id": "e3a89012-..." },
    { "name": "Rückkehrer77", "action": "restored_from_archive", "player_id": "7b0198aa-..." }
  ],
  "conflicts": []
}

3. Gezielter Transfer über Schnittstelle: POST /api/members/{name_or_id}/transfer

Führt denselben sicheren Transfer wie das interne R5-Tool aus – jetzt voll script- und app-fähig:

// Request Body
{
  "to_alliance": "INY"
}

// Response (200 OK)
{
  "ok": true,
  "player_id": "e3a89012-...",
  "player_name": "Lion Tooth",
  "from_alliance": "NxU1",
  "to_alliance": "INY"
}

DONATION_WEEK spendeTop20 Platz 1 bis 20 in der Allianz-Rangliste
VS_WEEK vsTop10 / vsTop30 Platzierung im wöchentlichen Duell
